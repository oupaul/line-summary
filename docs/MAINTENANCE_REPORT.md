# 維護記錄單產生器 操作設定手冊

把 LINE 匯出的客戶聊天記錄，整理成「維護記錄單」Excel：每筆含**需求提出時間、需求提出者、問題處理完成者、處理內容、狀態**，並附案件總數、已解決/待追數、各工程師處理件數。

> 本文件範例一律使用假名（客戶A、我方公司、工程師甲）。你的真實客戶與人員名稱只放在不會提交的 `tools/maintenance_local.json`。

---

## 1. 運作原理

```
LINE 匯出 .txt ──> chats/ ──> 切出日期範圍 ──> claude -p（不開任何工具）──> JSON ──> Excel（產出/）
                                                 ▲
                                    判讀規則：skills/maintenance-record/SKILL.md
```

- **Claude 只負責判讀**：誰提出、誰處理、結果如何、狀態是什麼。
- **Excel 由 Python 固定產出**：版面與統計每次一致。
- **聊天內容會交給 Claude 模型處理**，請依你的資料政策使用。聊天內容被當成不可信資料，不會照其中的指示行動；帳號密碼不會寫進輸出。

## 2. 前置需求（Mac）

| 項目 | 確認方式 | 沒有的話 |
|---|---|---|
| Python 3.9+ | `python3 --version` | `brew install python` |
| openpyxl | `python3 -c "import openpyxl"` | `pip3 install openpyxl` |
| Claude Code CLI，且已登入 | `claude --version` | 依官方文件安裝後執行 `claude` 登入 |

不需要 Flask，也不需要 LINE 電腦版保持開啟（這個工具只讀匯出的 `.txt`）。

## 3. 第一次設定（只做一次）

### 3.1 建立本機設定檔
```
cp tools/maintenance_local.example.json tools/maintenance_local.json
```
編輯 `tools/maintenance_local.json`：

| 欄位 | 說明 | 範例 |
|---|---|---|
| `customer` | 預設客戶名稱（用於 Excel 標題與檔名） | `"客戶A"` |
| `chat_keywords` | 用來挑聊天檔的檔名關鍵字（任一符合即納入） | `["客戶A", "王小明"]` |
| `team_prefix` | 我方人員在 LINE 顯示名稱的共同前綴，符合者列入工程師統計 | `"我方公司-"` |
| `engineers` | 沒有前綴、但也算我方工程師的名稱 | `["工程師甲"]` |
| `exclude` | 有前綴但不算工程師的人（業務、行政） | `["我方公司-業務乙"]` |

這個檔已被 `.gitignore` 忽略，不會被提交。**換電腦或重新 clone 時要重做這一步。**

### 3.2 讓啟動檔可執行（只有 clone 後失去權限才需要）
```
chmod +x 產生維護記錄單.command
```

### 3.3 第一次雙擊被 macOS 擋下
出現「無法驗證開發者」時：在檔案上按右鍵 → **打開** → 再按一次**打開**。之後就能直接雙擊。

## 4. 每次產生報告的流程

### 步驟 1：從 LINE 匯出聊天記錄（手動）
1. 在 LINE 開啟要整理的聊天室（群組或個人聊天都可以）。
2. 右上角選單 → **其他** → **傳送聊天記錄**（不同版本字樣可能略有差異）→ 存成 `.txt`。
3. 檔名格式通常是 `[LINE] 客戶A的聊天.txt`，**放進專案的 `chats/` 資料夾，覆蓋舊檔**。
4. 一個客戶有多個聊天室（群組＋各窗口個人聊天）時，全部都匯出，它們會一起判讀。

匯出檔格式（工具依此解析）：
```
2026/09/03（四）
11:27<Tab>客戶A-王小明<Tab>訊息內容
```

### 步驟 2A：用 GUI（建議）
1. 雙擊 `產生維護記錄單.command`，終端機視窗與瀏覽器會自動開啟。
2. **客戶名稱**：預設帶入設定檔的值，可修改。
3. **篩選聊天室**：輸入關鍵字（逗號分隔）會自動勾選符合的檔案，也可手動增減。清單會顯示每個檔案涵蓋的日期與大小，方便確認匯出的是不是最新。
4. **日期範圍**：自行選擇，或按「上個月／本月／最近兩個月」。
5. 按 **產生維護記錄單**，等待進度完成（幾十秒到數分鐘，視範圍而定）。
6. 完成後顯示案件總數、已解決/完成、進行中/待處理、技術/例行數與各工程師件數，按**下載**取得 Excel。檔案同時存在 `產出/`。
7. 用完關閉終端機視窗即可（視窗關閉，網頁就停止服務）。

### 步驟 2B：命令列
```
python3 tools/maintenance_report.py --since 2026-09-01 --until 2026-10-31
python3 tools/maintenance_report.py 客戶A --chat 關鍵字1 --chat 關鍵字2 --since 2026-09-01 --until 2026-10-31
```
未給客戶名稱與 `--chat` 時，使用設定檔預設值。

| 參數 | 說明 |
|---|---|
| `customer`（位置參數，可省略） | 客戶名稱，預設讀設定檔 |
| `--chat` | 聊天檔名關鍵字，可重複；預設讀設定檔 |
| `--since` / `--until` | 起訖日（含），格式 `YYYY-MM-DD`，必填 |
| `--model` | 指定模型，預設用 Claude Code 目前設定 |
| `--team-prefix` | 覆蓋設定檔的前綴 |
| `--engineer` / `--exclude` | 覆蓋設定檔的工程師／排除名單，可重複 |

### 步驟 2C：在 Claude Code 內
```
/維護記錄單 客戶A 2026-09-01 2026-10-31
```
Claude 會執行同一支腳本，並列出「處理中／待處理」案件請你覆核。

### 步驟 3：覆核（必做）
判讀結果是 Claude 依對話推論，請人工看過再交付：
- **黃底狀態列**（處理中／待處理）：確認是真的沒完成，還是對話裡沒留下完成紀錄。
- **跨月案件**：需求在範圍前提出、範圍內才跟進的，提出時間可能取範圍內第一則訊息。
- **處理完成者**：只應是實際動手處理的人；被 @ 但沒後續動作的不應列入。
- 處理內容寫「未見完成回報」的，補上實際結果。

## 5. Excel 內容

| 分頁 | 內容 |
|---|---|
| 總覽統計 | 技術／例行案件數、已解決/完成與待追數、各工程師處理件數（多人協作者各計 1 件，故加總大於案件數） |
| 技術問題與事件 | 故障、帳號權限、網路、主機、諮詢、文件、資安通報、請款資料等 |
| 例行IMS-POS櫃位設定 | 新櫃進駐／續約／撤換櫃的收銀機與刷卡機設定，同一批次合成一筆 |

明細欄位：編號、需求提出時間、需求提出者、問題/需求內容、問題處理完成者、處理內容、狀態。
狀態只會是：`已解決`、`已完成`、`處理中`、`待處理`、`已取消`。前三者之外的以黃底標示。

## 6. 調整判讀規則

所有判讀規則集中在 `skills/maintenance-record/SKILL.md`，改完存檔，下次執行即生效。常見調整：

| 想要 | 改哪裡 |
|---|---|
| 狀態判定更嚴格或更寬鬆 | 「status」那段 |
| 哪些工作算「例行」、如何合併批次 | 「category」與「判讀要點」 |
| 增加客戶專屬術語或固定規則 | 在「判讀要點」新增條目 |

Excel 版面（欄寬、顏色、分頁名稱）改 `tools/maintenance_report.py` 的 `build_xlsx`。

> 此檔會被提交到公開 repo。**規則中請勿寫入真實客戶名稱、人名或帳密。**

## 8. 疑難排解

| 現象 | 原因與處理 |
|---|---|
| 雙擊後說缺 openpyxl | 依提示執行 `pip3 install openpyxl` |
| 說找不到 `claude` | 安裝 Claude Code CLI；確認 `~/.local/bin/claude` 或 PATH 內有它 |
| 產生時顯示 claude 執行失敗／未登入 | 在終端機執行 `claude` 重新登入後再試 |
| 「chats/ 底下找不到…」 | 檔名沒有含關鍵字；到 `chats/` 確認檔名，或在 GUI 手動勾選 |
| 「所選聊天室在這段日期內沒有任何訊息」 | 日期選錯，或匯出檔不是最新；看 GUI 清單顯示的涵蓋日期 |
| 回覆兩次都無法解析成 JSON | 偶發；直接重試，或縮短日期範圍 |
| 範圍很長、跑很久 | 超過約 15 萬字會自動依月份分次呼叫，耗時與用量隨之增加；可分月產生 |
| 埠 8765 被占用 | `python3 tools/maintenance_gui.py --port 8800` |
| 網頁打不開／無法下載 | 確認終端機視窗還開著；只能用 `http://127.0.0.1:埠號/` 存取，其他主機名稱會被拒絕 |
| 工程師統計出現不該有的人／漏掉人 | 調整 `team_prefix`、`engineers`、`exclude` |
| 同一件事被拆成多筆或合併過頭 | 調整 SKILL.md 的「判讀要點」 |

## 9. 安全與資料

- 聊天內容含客戶與人員資料。`chats/`、`產出/` 已被 `.gitignore` 忽略，**不要手動 `git add -f`**。
- GUI 只綁定本機，並拒絕非本機的 Host 與路徑穿越下載。
- 每次產生都會消耗 Claude 用量；長範圍會多次呼叫。
- 推送到公開 repo 前，建議自行掃描：`git diff origin/main..HEAD | grep '^+'`，確認沒有真實名稱、IP、帳密。

## 10. 常見問答

**Q：它會自動從 LINE 抓資料嗎？** 不會。Mac 版 LINE 沒有可靠的自動匯出方式，匯出這步要手動。

**Q：一定要點 `.command` 嗎？** 不一定。命令列與 `/維護記錄單` 效果相同，`.command` 只是最省事的入口。

**Q：能一次處理多個客戶嗎？** 目前一次一個客戶。換客戶時在 GUI 改客戶名稱與關鍵字，或在命令列指定參數。

**Q：同一段範圍重跑，結果會一模一樣嗎？** 不保證。格式與統計邏輯固定，但判讀是模型推論，個別案件的合併方式或狀態可能略有不同，所以需要覆核。
